This release publishes the Policy API and serializable PDF pipelines as Maven Central libraries.

- `Policy.Profile` describes document, page, and bookmark checks as versioned data. Export JSON Schema, load JSON, and compile comparisons into ZIO Blocks SchemaExpr. Independent findings accumulate; unavailable or ambiguous evidence requires review.
- Compose, split, and rejoin typed PDF arrows, including conditional paths with named `yes`, `no`, and `unknown` branches. Saved pipelines preserve their branches and report execution decisions.
- Paper Machine exposes `check_pdf_pipeline`, `explain_pdf_pipeline`, and `run_pdf_pipeline`. Runs include byte hashes, branch evidence, skipped operations, and exact-output validation results. Its PDF/A-3b conversion arrow can validate a finished packet through Gotenberg and veraPDF.
- A policy preflight interpreter and an example petition policy demonstrate source citations, page-level evidence, and exact-file reports. These checks assist review; they do not establish compliance with every document requirement.
- Profiles saved with the earlier `court` and `filingType` metadata fields load as `authority` and `documentType`, including profiles embedded in saved pipelines.

All six Maven Central artifacts use version `0.4.0` and organization `io.github.adrielc`:

- `kyo-pdf_3`: JVM Kyo PDF core.
- `kyo-pdf-zio_3`: optional JVM ZIO adapter.
- `kyo-pdf-pipeline_3`: JVM Policy API and serializable arrows; depends on the public Kyo core and ZIO Blocks Schema 0.0.56.
- `kyo-pdf_native0.5_3`: Scala Native Kyo PDF core; requires Expat and zlib.
- `zio-pdf_3` and `zio-pdf_sjs1_3`: existing JVM and Scala.js APIs.

```scala
libraryDependencies += "io.github.adrielc" %% "kyo-pdf-pipeline" % "0.4.0"
```

The Policy and pipeline library is published for JVM. The Native pipeline remains an opt-in source build with separately supplied compatible dependencies; it is not a Maven Central artifact. Paper Machine, Gotenberg, PDFBox, and veraPDF are services or example dependencies, not dependencies of the pipeline library.

Earlier Kyo pre-release consumers must use the `io.github.adrielc.kyopdf` package, update the dependency organization, and recompile. Existing `zio.pdf` package names remain unchanged.

Release validation covers the JVM and Scala.js suites, the Native core and its external consumer, the Gotenberg MCP tests, package audits, and an independent Policy consumer that round-trips and runs a conditional policy pipeline. Publication verifies all six artifacts and runs the Policy consumer from Maven Central before creating this release.
