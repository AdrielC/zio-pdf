The Policy API and serializable PDF pipelines are now published for Scala Native 0.5 and Scala 3.

```scala
libraryDependencies += "io.github.adrielc" % "kyo-pdf-pipeline_native0.5_3" % "0.5.0"
```

The Native module uses the same Policy, arrow, JSON Schema, recipe-loading and execution sources as JVM. Compose, split, and rejoin arrows, serialize their definitions, and preserve `yes`, `no`, and `unknown` branches. Missing Policy evidence still requires review. Existing saved-profile metadata remains readable.

The Native dependency chain is public and reproducible. Five support artifacts under `io.github.adrielc:kyo-pdf-blocks-*` compile the needed ZIO Blocks v0.0.56 sources from public commit `b4523963f2981c15f15d0afa05b33a1ff0cf38a9`. The repository retains upstream copyright and Apache-2.0 notices, source checksums and documented Native adaptations. These are Kyo PDF support artifacts, not official upstream Native releases. No local JARs or custom resolvers are required, and consumers do not need experimental compiler flags.

Validation includes the upstream SchemaExpr suite on Native, portable JSON boundary tests, the shared Policy and pipeline suites, Gotenberg MCP tests on JVM, and independent JVM and Native consumers. The same consumer checks policy pass/fix/review findings and round-trips recipes through canonical and model-facing JSON, executes all three branch outcomes, and writes a PDF checked by qpdf and pdfinfo. The release workflow verifies all twelve public artifacts and runs both consumers from Maven Central before creating this release.

All artifacts use version `0.5.0` and organization `io.github.adrielc`. In addition to the existing JVM core, ZIO adapter and pipeline, Native core, and JVM/Scala.js legacy APIs, this release adds:

- `kyo-pdf-pipeline_native0.5_3`
- `kyo-pdf-blocks-schema_native0.5_3`
- `kyo-pdf-blocks-chunk_native0.5_3`
- `kyo-pdf-blocks-typeid_native0.5_3`
- `kyo-pdf-blocks-maybe_native0.5_3`
- `kyo-pdf-blocks-markdown_native0.5_3`

Native executables require the Scala Native toolchain, Expat and zlib. Native Schema supports compile-time nominal derivation rather than JVM runtime reflection or structural bindings. Its portable IDN helper follows upstream Scala.js behavior without IDN-to-ASCII conversion. Do not combine the support artifacts with a different Native runtime defining the same `zio.blocks` packages.

The pipeline supplies portable definitions and execution. Artwork, external PDF/A conversion and archival validation require a suitable `Services` interpreter. Paper Machine and its PDFBox/veraPDF services remain JVM applications.
