Kyo PDF 0.7.0 adds generic composable scans, shared byte ownership, and a PDF
parser migration for JVM and Scala Native.

```scala
// JVM core and optional FS2 integration
libraryDependencies += "io.github.adrielc" %% "kyo-pdf" % "0.7.0"
libraryDependencies += "io.github.adrielc" %% "kyo-pdf-fs2" % "0.7.0"

// Scala Native 0.5 and Scala 3
libraryDependencies += "io.github.adrielc" % "kyo-pdf_native0.5_3" % "0.7.0"
libraryDependencies += "io.github.adrielc" % "kyo-pdf-fs2_native0.5_3" % "0.7.0"
```

`Scan[I, O]` exposes path-dependent `State` and `Scan.Aux[S, I, O]`. Reusable
compiled plans create independent run state using typed ZIO Blocks Registers.
Long-specialized callbacks avoid state boxing. Sequential composition, fan-out,
conditional routing, contextual adapters and state remapping work with arbitrary
input types. Queues and graph sizes are checked. Scoped capture checking is an
opt-in experimental facade, covered by positive and negative compiler examples.

All FS2 3.14.0 `Scan` operation families have counterparts, tested directly
against FS2 on JVM and Native. Contextual adapters discard EOF outputs; ordinary
choice and sequential composition preserve the appropriate completion tails.
Optional FS2 pipes and Cats instances live outside the effect-free kernel.
Bounded batching favors throughput; `toPipeElementwise` yields after each input
when precise scan-step early termination matters.
Our pipe requires Cats Effect `Sync` for run-local mutable state and cleanup;
FS2's immutable implementation also supports pure pipes. This is behavioral
coverage within documented limits, not source or binary compatibility with FS2.

`ObservationSyntax.withInput` emits an input/event union, while `withInputEither`
preserves explicit provenance. Both use normal scan composition and forward the
original input references alongside incremental and EOF observations. Use owned,
immutable inputs or explicit leases; emitting a reference does not extend a
borrowed buffer's lifetime. Scala callbacks remain executable definitions, not
serialized model requests. Existing saved Policy and PDF recipes keep their
formats.

Shared byte probes coordinate independent reader positions over bounded owner
ranges. Explicit leases retain only their required ranges. Safe ingress makes
one ownership copy shared by all probes; borrowed ingress requires the producer
to keep storage immutable until it is released. Storage accounting measures
declared backing bytes, not heap or RSS. The optional ZIO adapter releases source
and scan scopes on success, failure, interruption and early completion.

PDF structural scanning, content parsing and typed object decoding now consume
shared byte views, avoiding whole-document character copies and final input
flattening. Structural boundaries feed the generic decoder once. Forward Length
resolution shares a lazy xref index. Array-based partial queries can exit early;
header and admission failures stop further streaming input. Full streaming
document decode still retains bounded input until EOF for forward references
and incremental cross-reference data. It does not provide disk spooling.

Streaming `PdfRead` admission is capped at 64 MiB and 65,536 blocks, in addition
to the caller's byte limit. New scan defaults allow 4,096 nodes and 1,024 pending
values, with checked maxima of 16,384 and 65,536. Nested contextual/state adapters
have a maximum depth of 64. These counts do not bound arbitrary callback payloads
or user state. Existing JVM Policy/pipeline APIs and the legacy API remain.

Public-source synthetic benchmarks and reproduction scripts are included in
`docs/pdf-parser-migration.md`. On the recorded stream-heavy synthetic workload,
full decoding improved on JVM and Native; token-only content parsing also
improved after replacing per-token regex compilation with ASCII grammar loops.
The tables retain the slightly slower small JVM decode and nearly flat cases.
The separate Scan/FS2 comparison records kernel losses as well as batched-pipe
wins on JVM and Native. Results qualify the documented local workload and
toolchain, not every PDF or production configuration.

All fourteen artifacts use organization `io.github.adrielc` and version `0.7.0`.
Native Schema support retains pinned public ZIO Blocks v0.0.56 sources, hashes
and licenses. No custom resolvers or supplied JARs are needed. Release gates run
JVM/Native suites, Gotenberg tool calls, capture compiler checks, artifact audits
and independent consumers. The independent JVM and Native consumers also run
the packaged FS2 integration; publication checks their Maven Central artifacts
before creating the GitHub release.
