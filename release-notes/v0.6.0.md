Kyo PDF 0.6.0 publishes checked pipeline results for JVM and Scala Native.

```scala
// JVM
libraryDependencies += "io.github.adrielc" %% "kyo-pdf-pipeline" % "0.6.0"

// Scala Native 0.5 and Scala 3
libraryDependencies += "io.github.adrielc" % "kyo-pdf-pipeline_native0.5_3" % "0.6.0"
```

Pipeline files now carry `PdfFile`, an immutable encoded payload with a checked
PDF header and a supported maximum of 64 MiB. This establishes a payload bound;
PDF syntax and PDF/A conformance still require inspection and validation.
Construction retains the existing byte vector without copying it.

Validation receipts hold a `VerificationResult` with `PdfAProfile` verdict keys.
Inspection receipts hold structured application reports and cannot supply
archival verdicts. Both retain the exact file supplied to the interpreter.
`ReportJson` parses an object-shaped report and checks length, nesting, node
count and duplicate fields. Independent report and profile errors accumulate
at the legacy service boundary, and unrequested verdicts are rejected.

The bounded writer checks encoded size before rendering streams, escaped
strings, decimal expansions and sparse cross-reference tables. Extreme decimal
normalization also returns a typed limit error. Live-value budgets count files
retained by receipts and deduplicate shared payloads.

### Migrating from 0.5.0

The Scala runtime-result API changes source and binary compatibility. Recompile
applications and update result handling:

```scala
run.outputs.foreach {
  case (_, PdfPipeline.Value.File(file)) =>
    val bytes: Vector[Byte] = file.bytes
  case (_, PdfPipeline.Value.Receipt(receipt)) =>
    val report = receipt.report.value // parsed JSON object
    val encoded: String = receipt.report.encoded
  case _ => ()
}
```

- Replace direct `Value.File(bytes)` construction with a checked `PdfFile`.
  `PdfFile.checked(bytes)` returns typed `DataIssue` failures.
- Read validation results from `PdfReceipt.Validation.result.verdicts`, keyed by
  `PdfAProfile`, and preserve `Verdict.Unable` as an unresolved outcome.
- Override typed `Services.verify`, `convert` and `inspect` when implementing a
  new service. Existing byte/string callbacks remain checked compatibility
  adapters. Existing `validate` implementations now need an `override` modifier.
- Runtime file limits must be positive and no greater than 64 MiB. Report limits
  are 1,048,576 UTF-16 code units, 64 nesting levels and 32,768 JSON nodes.

Saved recipe JSON, model-facing schemas and the studio result envelope retain
their existing formats. Policy definitions and composable arrows continue to
round-trip on JVM and Native, including distinct `yes`, `no` and `unknown`
branches. The legacy `zio.pdf` API is unchanged.

All twelve artifacts use version `0.6.0` and organization `io.github.adrielc`.
The Native Schema support artifacts retain their pinned public ZIO Blocks
v0.0.56 sources, checksums, licenses and documented adaptations. No local JARs
or custom resolvers are required. Native builds require the Scala Native
toolchain, Expat and zlib. External conversion and archival validation still
require an appropriate `Services` interpreter; Paper Machine remains a JVM app.

Release gates run the complete JVM and Native suites, Gotenberg and policy MCP
tests, artifact audits, and independent consumers. Publication verifies binary,
source, documentation and POM artifacts for all twelve coordinates, then executes
the shared Policy and conditional-pipeline consumer from Maven Central on both
JVM and Native before creating the GitHub release.
